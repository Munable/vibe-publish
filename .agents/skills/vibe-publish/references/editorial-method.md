# Editorial method

Use this before writing either language version. It prevents accurate source notes from becoming an accurate but scattered transcript.

## 1. Find the axis

Make a private fact ledger first. Then propose two or three possible answers to:

> What is the one judgment, change, or question the reader should carry away?

Choose one main axis by evidence strength, reader value, and how much of the supplied material it can honestly organize. Use at most one secondary axis. Label each source fact as:

- **axis** — directly states or changes the main point;
- **evidence** — proves or explains it;
- **boundary** — says what is unknown, unsupported, or out of scope;
- **support** — useful context that can be compressed or omitted.

The source version must preserve facts and the author's judgment. It does not preserve note order, repetition, filler words, or spoken fragments.

## 2. Compete structures, not templates

Choose only strategies that fit the material. Sketch two or three short outlines, then select the one with the clearest causal or argumentative movement.

| Strategy | Use when | Organizing movement |
|---|---|---|
| Change / turn | A before-and-after or decisive turn matters | Start with the change; include only the events needed to explain it |
| Decision / tradeoff | The value is why a choice was made | Decision, constraints, rejected options, cost, unknowns |
| Problem / diagnosis | The source is a failure, bug, or investigation | Symptom, narrowing evidence, current diagnosis, result, remaining doubt |
| Boundary / current state | Readers need to know what works and what does not | One central contrast, supported by evidence; never a feature inventory |
| Question / discussion | The real goal is useful peer feedback | Exact question, then only the background and constraints needed to answer it |
| Comparison / observation | There is a real A/B, before/after, or option comparison | Shared criteria, observed difference, consequence, applicability |

These are semantic routes, not visible section templates. Headings and lists are optional. Change one or two presentation dimensions when useful: entry point, progression relation, prose-versus-list balance, or reporting/analysis/questioning stance. Do not add randomness that changes facts or produces decorative variation.

## 3. Give the reader a human entrance

For a topic, select one concrete entry from the supplied material: an attempt that failed, a result
that contradicted an expectation, a decision the author made, or the exact question that remains. Use
one short paragraph, normally one to three sentences, to show why this person is writing this post now.
By the end of that paragraph, the reader should know the situation and the direction of the post.

This is not permission to invent a personality or feeling. Do not add a greeting, an industry-wide
preface, a rhetorical question whose answer is already known, or phrases such as "I want to share",
"let us look at", or "in today's rapidly changing world". A source without personal experience can
open on a concrete observed event or a precise question.

## 4. Draft for scanning

- Make the opening block and first screen carry the axis and current result or question. Put commands,
  measurements, implementation detail, and qualifications after the reader has a map.
- Give each paragraph one job and make its relation to the previous paragraph clear. One to four
  sentences is usually enough; vary paragraph length when the material needs it.
- Use two to four content-specific headings when a longer topic contains distinct evidence groups.
  Headings should describe this post's actual movement, not repeat fixed labels such as "Background",
  "Solution", and "Conclusion". A short post may need no headings.
- Use a list only when items are genuinely parallel or readers need to compare or scan them. Do not
  turn a narrative or causal explanation into a list merely to make it look structured.
- Prefer ordinary words, concrete nouns, and varied sentence length. "Natural" means low rhetorical
  distance and clear causality, not speech-to-text.
- Compress repeated conclusions, feature inventories, and chronology that does not change the
  decision, result, limitation, or open question. There is no universal word target; write the shortest
  complete version that preserves the fact ledger.
- If the source needs two independent takeaways, keep only the user-selected one in the current draft.
  Set the other material aside for a separately requested future post; never create or publish it
  automatically.
- End on the current result, limit, or next real question. A ceremonial recap or generic invitation is
  unnecessary.

Before translating, perform a private twenty-second scan using only the title, opening paragraph, and
headings. If those elements do not reveal what happened, why the author cares, and what the reader will
learn, restructure the source version.

## 5. Select the title after the body

Generate at least six candidates across at least three distinct angles compatible with the axis, such as concrete fact, tension/tradeoff, and precise question. They must not be six paraphrases of one formula.

Score each candidate out of 15:

- axis alignment: 0–3;
- specificity and information value: 0–3;
- honesty and scope discipline: 0–3;
- clear reading promise for the intended reader: 0–2;
- body fulfills the title: 0–2;
- English and Chinese titles keep the same axis and are natural: 0–2.

Reject a candidate immediately if it invents a result, exaggerates certainty, uses generic clickbait, promises content the body lacks, or changes angle between languages. Select the highest-scoring title, preferring the one the finished body most clearly fulfills. Ask the user to choose only when the strongest candidates would materially change the post's scope, factual emphasis, or position; do not create a title decision for a cosmetic difference.

When recent public forum titles are available, inspect a small set only to avoid duplication, stale formulas, and an alien editorial tone. They are style context, never source material.

## 6. Run two separate reviews

1. **Fidelity review:** both variants match the fact ledger, including every limit and unknown.
2. **Structure review:** state the axis in one sentence; verify every paragraph advances, proves, bounds, or usefully complicates it. Remove or relocate anything else.

Only then run the publication and governance review.
